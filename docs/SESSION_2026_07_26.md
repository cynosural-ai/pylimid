## Next: decision and utility nodes

Gibbs sampling is deferred. The next milestone is adding decision and utility
nodes to `graph/`, which unblocks the influence-diagram solving path.

### Decision node

A decision node represents a variable the agent controls. Key properties:
- `name` — identifier
- `parents` — information available when the decision is made (not a causal
  relationship; the decision "sees" these variables)
- `states` — available actions (tuple of labels)
- No `dist` — the decision's value is chosen, not sampled

The consistency model from `diagram.md` applies: a decision may exist before
its information parents are registered, and `validate()` catches dangling refs.

### Utility node

A utility node represents a payoff. Key properties:
- `name` — identifier
- `parents` — variables the utility depends on
- `values` — a function `(parent_assignments) -> float`, or a table over
  discrete parents

No `dist`, no `states` — utilities are deterministic numeric outputs.

### What changes in `InfluenceDiagram`

- `add_node` accepts `DecisionNode` and `UtilityNode` in addition to
  `ChanceNode`.
- `topological_sort` must respect the information constraint: decisions
  appear after their information parents, but chance and utility nodes must
  also be ordered correctly relative to decisions.
- `validate()` checks that utility parents exist, no cycles involving
  decisions, and the no-forgetting temporal order is respected.
- `snapshot()` tags nodes by type so inference/solve can route correctly.

### What changes in `inference/`

- `engine.py`: `_choose_engine` detects utility nodes → needs `solve()`, not
  `infer()`.
- `_infer_ve`: rejects diagrams with unbound decisions unless a `policy=` is
  provided (per the ADR).
- VE can be used on the decision-bound subgraph (collapses to BN).
- Future `bucket_elim.py` goes under a new `inference/id/` subdirectory.

### Test plan

- Decision node validity (field-level validation, same pattern as ChanceNode).
- Utility node validity.
- Diagram with all three node types: validation, snapshot, topological sort.
- `validate()` catches: unconfigured nodes, cycles through decisions, missing

- `infer()` with bound decisions uses VE on the subgraph.
- `infer()` with unbound decisions raises `InferenceError`.
