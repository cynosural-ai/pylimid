### PR A — exact influence-diagram solver (`inference/id/`)

The first solve milestone is done: **bucket elimination** — the exact, graph-native, numpy-only counterpart to variable elimination — computes optimal policies and expected utility for all-categorical LIMIDs.

#### Shared primitives

- **`inference/_factor.py`** — the `Factor` class promoted out of `ve/` so every graph-native engine uses the same primitive (`git mv`, history preserved). Also fixed a stale docstring reference in `ve/elim.py`.
- **`inference/_cpt.py`** — new shared builder module: `cardinalities` (name → domain size), `cpt` (a chance node's CPT factor, promoted from VE), and `utility_factor` (a utility node's `U(parents)` factor). Both engines consume them; `id/` never imports from `ve/`.

#### `inference/id/bucket_elim.py`

`solve(snapshot) -> Solution` returns a `Solution` dataclass holding:

- `policy`: decision name → `{info_set_assignment: action}` (the locally-optimal action per observable situation);
- `expected_utility`: the maximum expected total utility.

Algorithm (two factor types — this is the crux):

1. **Probability factors** (one CPT per chance node) **multiply**; **utility factors combine additively** into a single factor — the objective is `E[sum_k U_k]`, and multiplying utilities would compute `E[U1·U2]` instead of `E[U1+U2]`. Discovered while hand-verifying the two-decision test (EU = 50+40 = 90, not 50·40 = 2000).
2. Eliminate in **reverse topological order** (the Snapshot's order reversed, sinks first):
   - chance node → fold the CPT product into the utility factor (`sum_X P·U`) if it appears there, otherwise sum it out among the probability factors;
   - decision node → **max out**: best action per information-set assignment becomes the policy, the best value stays as the utility factor.
3. Combine the remaining scalars.

Two correctness subtleties surfaced and handled:

- **`Factor.__mul__` treats an empty-scope factor as the constant 1** (correct for VE's probabilities, wrong for a non-unit scalar utility). The final EU combines scalar factors directly, not via `*`.
- **Non-regular structures are detected, not silently mishandled**: `_max_out` raises `NotImplementedError` if a decision's best action would depend on a variable outside its information set (checked by grouping argmaxes per info-set assignment). This is the honest v0 boundary for the arc-reversal case. The `arc_reversal.py` helper from the plan was **omitted** — v0 does not need it, and the consistency check is a clearer boundary than a module that nothing calls.

### Cross-validation against pyAgrum's exact LIMID solver

`tests/validation/_id_fixtures.py` + `test_vs_pyagrum.py` follow the pgmpy-validation pattern for influence diagrams: each fixture defines the same LIMID for decisionpy and for pyAgrum (added to the `test` dependency group; note the module is `pyagrum` in v3), solves both, and asserts the **MEU** and the **per-decision optimal policies** agree (`abs=1e-5` — the decisionpy CPTs flow through JAX float32 arrays, so probabilities carry ~1e-6 rounding noise; both algorithms are exact).

Six fixtures, six passing tests: single decision, two independent decisions, empty info set, irrelevant info set, **nested two decisions** (D2's info set contains D1 — validates the backward-induction behavior), and a 3-state chance/outcome diagram exercising non-binary domains.

No solver bugs were found — the only issues were in the test harness itself:

- pyAgrum v3 API differences (lowercase `pyagrum` module; `MEU()` is a method returning `{"mean": ..., "variance": ...}`; `optimalDecision(name)` returns a 0/1 indicator tensor over `(decision, info parents)`).
- Two fixture bugs on my side (missing `X -> Y` and `D1/D2 -> U` arcs in the nested fixture), caught by the assertion that parent/evidence orders match.
- The float32 rounding looseness described above.
